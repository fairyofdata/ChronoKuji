# ADR-001: 2단계 하이브리드 점괘 생성 아키텍처 (Master DB + On-demand LLM)

- **상태 (Status)**: `Accepted`
- **결정 일자 (Date)**: 2026-08-31
- **의사결정자**: 시스템 아키텍트

---

## 1. 배경 및 문제 상황 (Context)
- 전통 일본 신사 오미쿠지는 7대 정통 등급(`대길~대흉`)과 정해진 운세 시(詩), 5대 세부운(소원, 연애, 재물, 사업, 여행 등)의 정형화된 형식을 따릅니다.
- 매 뽑기마다 LLM(Gemini API)을 직접 호출하여 점괘 전체를 생성할 경우:
  1. API 호출 비용 및 레이턴시(2~4초)가 발생하여 즉각적인 뽑기 손맛 저하.
  2. 환각(Hallucination)으로 인해 전통 등급 및 운세 시 형식의 일관성 훼손.

## 2. 의사결정 (Decision)
- **2단계 하이브리드 아키텍처 채택**:
  - **1단계 (기본 뽑기 - 0ms 지연)**: 12개 세계관 × 7대 정통 등급 = 총 84건의 정통 오미쿠지 마스터 데이터를 DB에 사전 캐싱하여 즉각 랜덤 추출.
  - **2단계 (개인화 심층 해석 - 토큰 소모)**: 유저가 자신의 고민을 입력하고 원할 때만 Google Gemini 2.5 Flash가 해당 세계관 캐릭터의 페르소나로 점괘의 5대 세부운을 융합 해석.

## 3. 결과 및 영향 (Consequences)
- **장점**:
  - 뽑기 시 레이턴시 0ms, 서버 비용 대폭 절감.
  - 정통 오미쿠지 형식의 100% 무결성 유지.
  - 유저 맞춤형 AI 상담의 가치와 토큰 소비 동기 부여 극대화.
